# 매뉴얼 사전 분석 개발 절차 — 본 에이전트 전달용

## 목적과 적용 범위

사용자는 매뉴얼을 확인하고 해석한 근거를 파싱·청크 설계에 반영하는 과정을 개발 절차에
명시하고 싶어 한다. 파서·청크 생성 기능을 새로 구현하거나 관련 규칙을 변경하기 전에
**대표 매뉴얼의 원문을 먼저 분석하고, 구현 후 추출 결과를 다시 대조한다.**

이 문서의 작성 자체가 원문 분석이나 코드 수정을 완료했다는 뜻은 아니다.
프로젝트의 AGENTS.md와 현재 파일·설정을 확인한 뒤 적용한다.

## 혼동하면 안 되는 두 작업

| 작업 | 시점 | 목적 |
| --- | --- | --- |
| 매뉴얼 사전 분석 | 파싱·청크 규칙을 설계하거나 변경하기 전 | 문서 구조와 적용 조건을 이해하고 처리 규칙의 근거 마련 |
| 파싱 결과 검수 | 실제 파싱 후, 검증된 근거의 색인 생성 전 | 원문과 추출 결과의 내용·관계·출처 보존 확인 |

개발 에이전트가 PDF를 보고 경고 영역을 지정한 일과, 실행 프로그램이 경고를 자동으로
판별하는 기능은 구분한다. 검토자가 작성한 영역 설정을 프로그램이 읽는 방식이라면
그 사실을 명시한다. 좌표·kind·reviewed 같은 필드가 있다는 이유로 자동 의미 검증이나
전체 매뉴얼 검토가 구현됐다고 설명하지 않는다.

## 개발 흐름

```text
대상 원본과 출처 확인
→ 대표 페이지 사전 분석
→ 분석 근거와 미확인 사항 기록
→ 파싱·블록·청크 규칙 설계
→ 구현
→ 동일 원문과 파싱 결과 대조
→ 필요한 규칙·보정 수정
→ 검색·답변 평가
```

### 1. 대상과 원본을 확인한다

- 차량 모델·연식·변속기·언어·문서명·출처 상태를 확인한다. 모르는 값은 임의로 채우지 않는다.
- 원본 파일의 SHA-256과 실제 페이지 수를 기록한다. 원본은 수정하거나 배포하지 않는다.
- 기존 manifest와 검토 자료가 있다면 원본 해시와 적용 범위가 일치하는지 확인한다.
- 기존의 분석 기록은 참고할 수 있지만 새 문서에도 유효하다고 자동으로 간주하지 않는다.

### 2. 대표 페이지를 선택하고 시각적으로 읽는다

일반 본문뿐 아니라 다음 유형을 포함한다. 해당 유형이 없거나 확인하지 못했으면 기록한다.

- 다단 본문과 다음 페이지로 이어지는 절.
- 표의 병합 셀·머리글·행/열·단위·각주.
- 경고·주의 문구, 아이콘, 설명에 붙은 적용 조건.
- 수동/DCT 또는 다른 사양의 설명이 혼재한 페이지.
- 그림 속 정보, 스캔 페이지, 빈 추출 또는 읽기 순서가 불명확한 페이지.

PDF를 이미지로 렌더링해 원문 배치를 확인한다. 텍스트가 추출됐다는 사실만으로
표의 관계나 경고 범위까지 올바르게 읽었다고 판단하지 않는다.

### 3. 구현에 필요한 판단을 기록한다

각 대표 영역에 대해 다음을 정리한다.

| 항목 | 기록할 내용 |
| --- | --- |
| 위치 | PDF 페이지, 인쇄 번호, 절 제목, 필요하면 영역 좌표 |
| 읽기 순서 | 열·문단·표를 어떤 순서로 해석해야 하는지 |
| 표의 관계 | 항목·조건·값·단위·머리글·각주가 어떻게 대응하는지 |
| 경고의 범위 | 경고 원문이 어느 설명이나 표 행에 적용되는지 |
| 차량 적용 범위 | common/dct/manual/unknown 판정과 원문 근거 |
| 청크 묶음 | 함께 보존할 제목·본문·표 행·조건·경고·관련 페이지 |
| 미확인 사항 | OCR·그림 해석·추가 원문 확인이 필요한 영역 |

‘주의’나 ‘경고’ 표제는 판단의 단서다. 표제와 아이콘만으로 적용 대상을 확정하지 말고
주변 설명 및 연결된 페이지와 대조한다. 변속기 언급이 없다는 이유로 common으로 분류하지 않는다.

좌표 기반 보정이 필요하면 **원본 해시·PDF 페이지·좌표계·적용 근거**를 함께 기록한다.
PDF 좌표와 렌더링 이미지의 픽셀 좌표를 혼동하지 않는다. 특정 원본의 좌표를 다른 문서나
개정판에 그대로 적용하지 않는다.

### 4. 기록을 바탕으로 처리 규칙을 설계한다

- 문서에서 확인한 구조를 기준으로 블록 경계와 청크 연결을 결정한다.
- 제목·머리글·단위·필수 각주·경고가 분리되지 않도록 한다.
- 자동 규칙과 검토자가 작성한 보정을 구분하고 각각의 적용 조건을 설명한다.
- 특정 문서만 처리하는 보정을 일반적인 자동 분석 기능처럼 설명하지 않는다.
- 수동 전용 근거는 DCT 근거에 포함하지 않는다. 적용되는 필수 경고가 미검토라면
  경고만 조용히 버리지 말고 해당 근거 묶음의 미검증 상태를 기록한다.
- 길이 제한 때문에 내용이 제외되면 대상과 이유를 추적할 수 있게 한다.

### 5. 구현 후 동일 원문과 결과를 다시 대조한다

- 선택한 대표 페이지의 원문과 Page/Block/Chunk 결과를 비교한다.
- 표의 항목과 수치가 서로 바뀌지 않았는지, 단위·조건·경고가 보존됐는지 확인한다.
- PDF 페이지와 인쇄 번호가 원본 위치에 정확히 연결되는지 확인한다.
- 원문에 필요한 근거가 있는데 추출·발췌·길이 제한 때문에 누락되지 않았는지 확인한다.
- 자동 테스트 성공과 원문 의미 검토를 구분한다. 발췌의 존재만으로 주장 전체가
  뒷받침된다고 간주하지 않는다.

## 분석 기록의 최소 형식

원문·렌더링·추출 전문이 들어 있는 상세 자료는 프로젝트에서 지정한 로컬 데이터 경로에
보관하고 Git/패키지 배포에서 제외한다. 개발 문서에는 필요한 처리 규칙·근거 위치·한계만 남긴다.

```markdown
# 매뉴얼 사전 분석 기록

- 대상 문서 / 차량 / 연식 / 변속기:
- 출처 및 검증 상태:
- 원본 SHA-256 / 전체 페이지 수:
- 검토 날짜 / 검토자 / 검토자 유형(사람 또는 에이전트):
- 검토한 PDF 페이지·인쇄 번호·영역:
- 관찰한 표·본문·경고 구조:
- 적용 범위 및 경고 연결 판단 근거:
- 채택할 처리 규칙 / 문서별 보정:
- 미확인·미검토 영역과 필요한 후속 작업:
- 구현 후 원문 대조 결과:
```

대표 페이지 분석을 전체 문서 검토로 표시하지 않는다. 문서·파서·보정 규칙이 바뀌면
기존 분석이 유효한지 확인하고 영향받는 영역을 다시 대조한다.

## 본 에이전트에게 전달할 요청

이 문서를 읽고 **‘매뉴얼 사전 분석 → 구현 → 파싱 결과 검수’**를 개발 절차로 반영한다.
현재 구현에서 사전 검토 자료에 의존하는 부분과 자동 처리하는 부분을 사용자에게 구분해 설명한다.
새로운 자동 검토 기능의 구현은 이 문서 작성과 별개 범위로 다룬다.

이 문서는 전달용 절차 문서다. 기존 AGENTS.md·README·OpenSpec 산출물과 소스 코드를
이 문서 작성 작업에서 함께 수정한 것은 아니다.
