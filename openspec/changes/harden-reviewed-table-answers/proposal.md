# Proposal

## Why

첫 기준선은 인용문에 숫자가 있는지만 검사하므로 표의 대상과 값을 바꾼 답변도 통과할 수 있다.
리뷰에서 확인한 평가·근거 누락·오류 처리 결함을 수정하고, 원문 사전 분석을 설계의 입력으로 삼아
검토된 표의 의미 관계가 답변까지 보존되게 한다.

## What Changes

- 파서·청크 규칙 변경 전에 대표 PDF를 시각적으로 분석하고, 구현 후 같은 원문과 결과를
  대조하는 절차를 필수 선행 작업 및 인수 조건으로 명시한다.
- 검토 자료에 대상·항목·조건·값·단위·필수 각주/경고·원본 위치를 묶은 표 사실을 기록한다.
  모델은 검색된 사실 ID를 선택하고 프로그램이 수치 문장과 인용을 구성한다.
- 일반 설명과 섞인 답변에서도 표 수치의 자유 생성 우회를 차단한다. 미검토 구조, 조건 누락,
  상충과 필수 경고 누락은 명시적으로 유보하거나 해당 근거 묶음을 제외한다.
- 발췌/문맥 제한에 따른 제외를 추적하고 PDF/인쇄 페이지 대응을 보존한다. 수동 전용 선택
  링크와 미검토 필수 링크를 구분해 무관한 근거 때문에 색인 전체가 중단되는 문제를 수정한다.
- 차량 사양 판정의 문맥 오인, 유료 검색 이전 설정 검사 누락, SDK 응답 검증 예외 처리를 수정한다.
- 답변 가능 사례 기준 통과율과 파싱을 포함한 품질 게이트를 적용한다. 리뷰 회귀 테스트를
  기본 수집에 포함하고 기존 평가 기록의 지표를 API 재호출 없이 정정한다.
- **BREAKING**: 검토 자료·파싱·청크·인용 JSON 계약에 버전을 부여하고 표 사실과 페이지 대응을
  추가한다. 기존 산출물은 무검증 자동 변환하지 않으며 검토 보완 후 파싱·색인을 재생성한다.

## Capabilities

### New Capabilities

없음. 기존 네 capability에 요구사항을 추가하거나 수정한다.

### Modified Capabilities

- `manual-ingestion`: 사전 분석과 사후 원문 대조, 검토 이력, 구조화된 표 사실 및 출처 계약.
- `vehicle-scoped-retrieval`: 표 사실·페이지 대응 보존, 필수/선택 링크 처리 및 계약 호환성.
- `grounded-manual-answers`: 사실 ID 기반 수치 답변, 발췌·문맥 누락 보고, 사전 검사 및 장애 구분.
- `rag-quality-evaluation`: 정확한 분모·파싱 게이트, 표 관계 회귀 검증, 부분 평가 결과 보존.

## Impact

- 대상은 CN7N/2025/DCT와 기존 대표 질문 16개다. 원문 사전 분석의 출발점은 PDF
  13·16의 표와 200·205·207·208·212의 본문/경고, 6의 빈 페이지이며 분석 결과로 범위를 보완한다.
- 주요 변경 대상: `contracts.py`, `parsing.py`, `chunking.py`, `retrieval.py`, `answering.py`,
  `openai_adapter.py`, `pipeline.py`, `evaluation.py`, CLI 경계, 테스트 및 평가 사례.
- 구현 시 `AGENTS.md`, `README.md`와 검증 문서에 절차·계약·재생성 방법을 반영한다.
  근거 문서는 `docs/code-review-2026-10-08.md`, `docs/manual-preanalysis-handoff.md`다.
- Python 3.11, pdfplumber 0.11.10, OpenAI SDK 3.26.0, text-embedding-3-small/1536,
  gpt-5-mini, FAISS를 유지한다. 새 외부 서비스나 의존성을 전제로 하지 않는다.
- 원문·렌더링·상세 검토 자료는 로컬 제외 경로에 보관한다. PDF 및 비밀값은 배포하지 않는다.
- 전체 매뉴얼 검토, 자동 OCR/표 의미 해석, 다른 차량 지원, UI, 일반 문장 의미의 완전한
  자동 검증은 범위 밖이다. 이번 제안 작성 자체는 사전 분석이나 구현 완료를 의미하지 않는다.
