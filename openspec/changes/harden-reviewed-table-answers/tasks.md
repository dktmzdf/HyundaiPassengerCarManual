# Tasks

## 1. 구현 전 매뉴얼 사전 분석

이 그룹의 원문 분석·판단 기록을 마친 뒤 파싱·청크 규칙과 사실 계약을 구현한다.
문서 작성만으로 원문 분석을 완료 처리하지 않는다.

- [ ] 1.1 원본 PDF의 해시·전체 페이지 수·차량/출처 상태와 기존 검토 설정을 대조하고 활성 데이터 세대를 기록한다. 원본 불변과 설정의 해시 일치로 완료를 확인한다.
- [ ] 1.2 PDF 13·16 및 200·205·207·208·212·6을 렌더링해 표·다단·경고·혼합 사양·빈 추출을 분석한다. 필요한 연결 페이지, 읽기 순서, 사실/조건/각주 관계와 미확인 유형을 기록한 로컬 분석 자료로 확인한다.
- [ ] 1.3 검토자·유형·날짜·원본 위치·좌표계·판단 근거를 포함한 사전 분석 기록을 완성하고 사실 및 required/optional 연결 목록을 정한다. 각 판단이 원문 위치를 가리키고 미확인 관계는 승인하지 않았는지 대조한다.
- [ ] 1.4 AGENTS.md와 README에 사전 분석 → 구현 → 동일 원문 대조 절차를 반영하고 docs에 공유 가능한 규칙/위치/한계를 정리한다. 인수인계 문서의 항목 누락과 원문·렌더링·비밀값 혼입이 없는지 확인한다.

## 2. 검토 및 표 사실 데이터 계약

- [ ] 2.1 PageRef, 검토 이력, TableFact/Quantity와 EvidenceLink의 버전 있는 계약을 추가한다. 합성 자료로 null 인쇄 번호, 범위·상하한·복수 단위, 잘못된 해시/자료형/참조/ID의 거부를 검사한다.
- [ ] 2.2 파서의 검토 설정 적용을 새 계약에 연결하고 후보 생성·사후 대조·승인 상태를 구분한다. 승인 누락 및 원본/처리/설정 변경으로 낡은 승인을 재사용할 수 없는지 테스트한다.
- [ ] 2.3 분석 결과로 로컬 검토 파일을 보완하고 이전 related_ids를 근거에 따라 필수/선택으로 분류한다. 자동 의미 추출로 표시하지 않으며 각 사실과 연결의 원문 추적 가능성을 확인한다.
- [ ] 2.4 README에 새 검토 계약과 구버전 거부·재처리 방법을 기록하고 새/변경 구현 함수의 한국어 docstring을 갱신한다. 예시에는 합성 값만 사용하고 tests의 주석은 필수로 확대하지 않는다.

## 3. 청크·출처·검색 보존

- [ ] 3.1 사실·PageRef·필수 맥락을 청크와 검색 결과까지 전달하고 인쇄 번호 평행 목록을 교체한다. 앞 페이지의 인쇄 번호가 null인 다중 페이지 청크의 저장/복원·인용 매핑을 테스트한다.
- [ ] 3.2 필수 링크의 미검토/부적합은 영향 묶음만 제외하고 선택 수동 행은 필터링한다. 정상 묶음의 색인 지속, 제외 ID/사유, 없는 링크/중복 ID의 계약 오류, 정상 청크 0개일 때 이전 색인 보존을 테스트한다.
- [ ] 3.3 파서·청크·사실 계약 버전을 처리 fingerprint와 색인 메타데이터에 반영한다. 구버전 거부, 사실만 바뀐 세대 혼용 거부, 동일 임베딩 계약/텍스트의 캐시 재사용을 테스트한다.
- [ ] 3.4 새 규칙으로 대표 페이지·블록·청크·사실 후보를 만들고 그룹 1의 동일 원문과 시각적으로 대조한다. 표 관계·출처·경고 보존 결과를 기록하고 미확인 묶음은 미승인으로 유지한 검토 자료로 완료를 확인한다.
- [ ] 3.5 README에 청크 제외 사유와 파싱→색인 재생성 및 구버전 코드/세대 복원 방법을 기록한다. 합성 세대 전환/실패 테스트로 기존 정상 결과 보존과 중간 불일치 거부를 확인한다.

## 4. 사실 선택 및 수치 답변

- [ ] 4.1 모델의 표 출력은 제공된 evidence_id/fact_id 선택으로 제한하고 로컬 렌더러가 대상·조건·값·단위·인용·경고를 구성하게 한다. 미제공 ID, 다른 근거 ID, 모델 작성 값/페이지를 거부하는 테스트를 추가한다.
- [ ] 4.2 표/혼합 답변의 일반 설명은 허용된 발췌 선택으로 제한하여 자유 수치 재작성 경로를 닫는다. 앞뒤 값 교환, 오일 항목 교환, 숫자 대신 글자로 쓴 우회, 미구조화 표의 수치 답변을 합성 응답으로 검사한다.
- [ ] 4.3 조건별 사실 묶음 출력 또는 확인 요청, 동일 조건 값 충돌, 필수 경고 누락 처리와 유보 사유를 구현한다. 조건 없는 질문·조건별 값 차이·실제 충돌·일부 조건만 검색된 경우를 테스트한다.
- [ ] 4.4 발췌 후보와 문맥 선택에서 묶음/구간별 제외 ID·사유를 남긴다. 긴 표와 후반 경고의 보존 또는 명시적 제외, 모든 근거 예산 초과 시 모델 무호출 및 context_budget 부족 상태를 테스트한다.
- [ ] 4.5 README에 사실 기반/일반 답변의 차이, 처리 범위·유보·상충·문맥 제한 예시를 합성 입력으로 기록한다. CLI 출력과 문서의 필드·상태가 일치하는지 확인한다.

## 5. 실행 전 검사 및 SDK 오류 처리

- [ ] 5.1 ask와 평가가 공유하는 preflight를 검색 전에 적용한다. 모델 설정 누락·명시적 다른 연식/수동 차량에서 임베딩 무호출, 보증 연도·DCT 수동 모드의 정상 진행, search의 생성 설정 독립성을 테스트한다.
- [ ] 5.2 설치된 OpenAI SDK 3.26.0 예외 계층을 확인하고 응답 검증 등 예상 가능한 SDK 오류를 단계별 장애로 변환한다. 인증·할당량·잘못된 응답 무재시도, transient 최대 재시도/deadline, CLI traceback·비밀값 비노출을 모의 호출로 테스트한다.
- [ ] 5.3 README와 관련 docstring에 입력/설정 오류, 사양 확인, 검색/생성 장애의 실행 순서와 종료 동작을 갱신한다. 실제 호출 없이 CLI 경계 테스트로 문서화한 상태와 종료 코드를 확인한다.

## 6. 평가 기준과 결과 보존

- [ ] 6.1 리뷰 테스트를 test_*.py로 옮겨 기본 수집에 포함하고 중복된 재현은 통합한다. pytest --collect-only로 수집을 확인하고 리뷰 10개 항목 각각의 회귀 테스트 대응을 기록한다.
- [ ] 6.2 answerable 분자/분모와 파싱 포함 공통 게이트를 구현한다. 9/10+6/6, 7/8+8/8, 답변 가능 0개, 파싱 실패/누락, 미판정, local/live/judge 일관성을 테스트한다.
- [ ] 6.3 기존 16개 평가 사례에 원문에서 확인한 사실·조건·경고·출처와 검토 이력을 반영한다. 관계 보존 검사가 문자열 존재만으로 통과하지 않으며 무관한 사실 선택은 답변 실패로 판정되는지 검사한다.
- [ ] 6.4 사례별 원자적 checkpoint와 완료 보고서 게시를 분리한다. 후속 SDK 오류 및 저장 중 실패를 주입해 완료 사례·확인된 usage·이전 정상 보고서가 보존되고 평가 실패가 CLI 종료 코드에 반영되는지 테스트한다.
- [ ] 6.5 과거 상세 판정에서 API 호출 없이 9/10 통과율을 재계산한 별도 로컬 결과를 만든다. 원본 보고서 해시 불변, 계산 버전·출처 연결, 과거 파싱과 새 관계 검증의 구분을 확인하고 공유 평가 요약/검증 문서를 정정한다.
- [ ] 6.6 README에 평가 명령, 검토자 유형, checkpoint와 완료 보고서 구분, 미실행·미판정·실패 의미를 기록한다. 합성 평가의 저장 결과와 CLI 출력으로 예시를 확인한다.
